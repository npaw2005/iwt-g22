1. Execution Context & Script Placement

Syllabus TheorySingle-Threaded Client Engine

JavaScript is a lightweight, interpreted, prototype-based scripting language executed sequentially on the client browser:

  • Script Tag Placement:
    • <head> placement: Script executes before the HTML body is parsed. If the script attempts to access form elements, document.formName evaluates to undefined because the DOM tree has not yet been constructed!
    • Bottom-of-Body placement: Placing <script> immediately before </body> guarantees all form controls and HTML elements are rendered in memory before JavaScript executes.
  • defer vs async:
    • async: Downloads script asynchronously while HTML parses, executes immediately upon download (blocks parser during execution).
    • defer: Downloads script asynchronously, but defers execution until the HTML document has finished parsing.

3. Data Types, null vs. undefined & javascript:void(0)

Syllabus TheoryPrimitive Types & Historical Quirks
  • Primitive Types: Number, String, Boolean, Null, Undefined, Symbol (ES6), BigInt.
  • The Fundamental null vs undefined Distinction:
    • undefined: Variable declared but not assigned a value; or a function returning without a value. typeof undefined === "undefined".
    • null: Intentional programmatic representation of an empty object pointer. typeof null === "object" (historical JS quirk).
  • javascript:void(0): The void operator evaluates the given expression (0) and unconditionally returns undefined. Frequently used in anchor tags (<a href="javascript:void(0)">) to prevent browser navigation, URL hashing, or scrolling to top.

4. Arithmetic Operators & Number Coercion

Syllabus Theory+ vs -, *, /, %
  • The + operator performs string concatenation if either operand is a string: "10" + 5 evaluates to string "105".
  • All other arithmetic operators (-, *, /, %) automatically coerce operands to numbers:
    • "10" - 5 evaluates to numeric 5.
    • "10" * "2" evaluates to numeric 20.
    • "10" / "2" evaluates to numeric 5.
    • "10" % 3 evaluates to numeric 1 (remainder).
    • "abc" - 5 evaluates to NaN (Not-a-Number).

5. Comparison Operators & Strict Equality (== vs ===)

Syllabus TheoryLoose vs Strict Equality
  • Loose Equality (==): Performs implicit type coercion to convert operands to a common type before comparison:
    • 10 == "10" → true (String coerced to Number).
    • 0 == false → true (Boolean coerced to Number: false → 0).
    • null == undefined → true.
    • "" == 0 → true.
  • Strict Equality (===): Checks both value AND data type without coercion:
    • 10 === "10" → false (Number vs String).
    • 0 === false → false (Number vs Boolean).
    • null === undefined → false.

6. Logical Operators & Short-Circuit Evaluation

Syllabus Theory&&, ||, !

JavaScript logical operators utilize short-circuit evaluation:

  • expr1 && expr2: If expr1 is falsy, short-circuits immediately and returns expr1 without evaluating expr2.
  • expr1 || expr2: If expr1 is truthy, short-circuits immediately and returns expr1 without evaluating expr2.
  • Falsy values in JS: false, 0, "" (empty string), null, undefined, NaN. All other values are truthy.

7. Branching & The Switch Fallthrough Trap

Syllabus Theoryswitch Case Matching

The switch statement matches expressions using strict equality (===).

The Fallthrough Trap (EXAM FAVORITE!):

If a break statement is omitted at the end of a matching case block, JavaScript falls through into every subsequent case block, executing all subsequent code regardless of whether the condition matches, until it hits a break or ends!

8. Loops, Modulo Tracing & Labeled Statements

Syllabus Theorywhile, do-while, for & Labels
  • while (condition): Pre-condition check (may execute 0 times).
  • do { ... } while (condition);: Post-condition check (guaranteed to execute at least once).
  • for (init; condition; increment): Standard counter loop.
  • Labeled Statements: Assigns an identifier label to an outer loop, permitting break label; or continue label; to escape deeply nested loops directly.

9. Functions, Scope & Arguments Object

Syllabus TheoryDeclaration, Return & Arguments

Functions encapsulate reusable procedural logic:

  • function funcName(param1, param2) { return val; }
  • If no return statement exists, the function automatically returns undefined.
  • arguments object: An array-like object available within all non-arrow functions containing all passed parameters (arguments[0], arguments.length).

12. Form Submission Event Pipeline & The Mandatory return Keyword

Syllabus Theoryonsubmit="return validate()"

The Mandatory return Rule (CRITICAL!):

When wiring validation to a form: <form onsubmit="return checkApplication()">:

  • The return keyword is compulsory.
  • If return is included and checkApplication() returns false, the browser receives return false; and cancels the default HTTP form submission.
  • If return is omitted (e.g. onsubmit="checkApplication()"), the function runs and returns false, but the onsubmit event handler itself returns undefined, which the browser treats as truthy and submits the form anyway!

13. Non-Regex Algorithmic Validation (Email, NIC & Dates)

Syllabus TheoryPure String Algorithmic Inspection

The university syllabus specifically avoids regex for introductory students, mandating direct algorithmic checks:

  1. Algorithmic Email Validation (indexOf / lastIndexOf):
    • Condition 1: atpos < 1 (@ must not be the very first character).
    • Condition 2: dotpos - atpos < 2 (period . must occur at least two positions after @).
  2. Character Loop Traversal: Looping through characters with charAt(i) to ensure all characters are ASCII digits between "0" and "9".
  3. Date Object Comparisons: Splitting date strings with split("-"), generating new Date(y, m-1, d), and comparing timestamps against new Date().

14. Dialog Boxes & Client Cookies Architecture

Syllabus TheoryDialog Boxes + document.cookie
  • alert("msg"): Informational notification with OK button.
  • confirm("prompt"): Binary confirmation returning true or false.
  • prompt("text", "default"): Returns user text string or null.
  • Cookie Management:
    • Set cookie: document.cookie = "key=val;expires=" + date.toUTCString() + ";path=/";
    • Read cookie: var arr = document.cookie.split(';');
    • Delete cookie: Set expiry date to a past timestamp (e.g. now.setMonth(now.getMonth() - 1);).
