1. Execution Context, Script Tags & Scope Mechanics

Syllabus Theory <script> Tag & Variable Declarations

JavaScript is a dynamically typed, single-threaded, client-side scripting language executed directly by the browser's JavaScript engine (V8, SpiderMonkey):

  • Script Tag Embedding: Placed inside <script type="text/javascript"> ... </script>. In legacy curricula, code was frequently enclosed within HTML comment blocks (<!-- //-->) to prevent older non-JS browsers from rendering script text.
  • Head vs Bottom-of-Body Placement: Scripts placed in the <head> execute before the DOM has loaded. Form validation scripts targeting HTML form elements must be placed at the bottom of the body or executed inside window.onload so that the form DOM nodes exist when the script executes.
  • Variable Scoping:
    • var: Function-scoped (or globally scoped if declared outside functions). Hoisted to the top of its execution context with an initial value of undefined.
    • let & const: Block-scoped (contained within curly braces { ... }). Subject to Temporal Dead Zone (TDZ).
    • Implicit Globals: Assigning to an undeclared variable (e.g. atpos = email.indexOf("@"); without var) automatically binds that identifier to the global window object!
  • The null vs undefined Distinction:
    • undefined: Variable has been declared but has not been assigned a value; or a function returns without an explicit return statement. Type: undefined.
    • null: Intentional programmatic representation of "no value" or empty object reference. Type: object (a famous historical JS quirk!).
    • javascript:void(0): Evaluates expression 0 and returns undefined, effectively preventing hyperlinks from navigating or scrolling to top.

2. Operators, Type Coercion & Strict Equality (== vs ===)

Syllabus Theory Loose vs Strict Type Comparison

Understanding implicit type coercion is a critical exam topic:

  • Loose Equality (==): Converts both operands to a common type before performing comparison.
    • 10 == "10" → true (String coerced to Number).
    • 0 == false → true (Boolean coerced to Number: false → 0).
    • null == undefined → true (Special rule: equal only to each other).
    • "" == 0 → true (Empty string coerced to 0).
  • Strict Equality (===): Checks both value AND data type with zero coercion.
    • 10 === "10" → false (Number vs String).
    • 0 === false → false (Number vs Boolean).
    • null === undefined → false (Object vs Undefined).
  • Arithmetic vs Concatenation:
    • The + operator concatenates if either operand is a string: "5" + 2 evaluates to "52".
    • Other arithmetic operators (-, *, /, %) always coerce strings to numbers: "10" - 3 evaluates to numeric 7.

3. Control Flow, Switch Fallthrough & Labeled Loops

Syllabus Theory Loops & Branching Logic

The Switch Case Fallthrough Trap:

In JavaScript, a switch statement matches cases using strict equality (===). If a break statement is omitted, execution cascades into all subsequent case statements regardless of whether their condition matches!

Labeled Loops (Break/Continue with Labels):

A label provides an identifier to a statement or loop block, allowing break or continue to target an outer nested loop directly:

outerloop:
for (var i = 0; i < 3; i++) {
    for (var j = 0; j < 3; j++) {
        if (i == 1 && j == 1) {
            break outerloop; // Terminates the entire outer loop, not just inner!
        }
        document.write(i + "," + j + " ");
    }
}
// Output: 0,0 0,1 0,2 1,0

4. DOM Level 0 Form Access & Event Architecture

Syllabus Theory document.forms Hierarchy

The UCSC curriculum exclusively teaches DOM Level 0 for form handling. Elements are accessed by walking down the window-document-form hierarchy:

  • Access by form name: document.formName.inputName.value.
  • Access by form index: document.forms[0].elements[0].value.
  • Form Control Value Access:
    • Text, Password, Email, Date: document.myForm.username.value.
    • Checkbox: document.myForm.agree.checked (Returns boolean true or false).
    • Radio Buttons: Loop through array document.myForm.gender and check [i].checked.
    • Dropdown Select: document.myForm.country.value or document.myForm.country.selectedIndex.
  • The onsubmit="return validate()" Rule (CRITICAL!):
    • The inline attribute MUST include the return keyword: <form onsubmit="return checkForm()">.
    • If the function returns false, the browser cancels the default HTTP submission. If return is omitted (e.g. onsubmit="checkForm()"), the form will submit anyway even if the function returns false!

5. Form Validation Algorithms: Email, NIC & Dates

Syllabus Theory Pure Algorithmic Validation without Regular Expressions

The university syllabus specifically forbids or discourages regex for introductory students, testing direct string manipulation algorithms instead:

  1. Algorithmic Email Validation (indexOf / lastIndexOf):

    From 13_JS_FormValidation.pdf slide 14, an email is validated with two mathematical conditions:

    • Condition 1: atpos < 1 (@ must not be the first character).
    • Condition 2: dotpos - atpos < 2 (the period . must occur at least two characters after @).
  2. Character-by-Character String Inspection:

    Looping through characters using charAt(i) to ensure all characters are ASCII digits between "0" and "9".

  3. Temporal Validation (Date Objects):

    Splitting date strings (YYYY-MM-DD) into year, month, day components, constructing a new Date(y, m-1, d), and comparing timestamps against current system time (new Date()).

Past Paper Alert & Traps Master Email Validation Template 
function validateEmail() {
    var emailID = document.myForm.EMail.value;
    var atpos = emailID.indexOf("@");
    var dotpos = emailID.lastIndexOf(".");

    if (atpos < 1 || (dotpos - atpos < 2)) {
        alert("Please enter a valid email address.");
        document.myForm.EMail.focus();
        return false;
    }
    return true;
}

6. Dialog Boxes & Dangerous Action Confirmation

Syllabus Theory alert, confirm & prompt

JavaScript provides three native modal popup boxes:

  • alert("text"): Information notification. Displays text with single OK button. Execution halts until closed.
  • confirm("question"): Binary consent dialog. Displays OK and Cancel buttons. Returns boolean true if user clicks OK, or false if Cancel is clicked.
  • prompt("label", "default"): Text input prompt. Returns the string entered by user, or null if user cancels.

7. Client-Side Cookies Architecture

Syllabus Theory 8_JS_cookies.pdf Curriculum

Cookies store small text key-value pairs directly in the client browser across sessions:

  • Cookie Format: key=value;expires=date_string;path=path;domain=domain;secure
  • Setting a Cookie: 
    // Simple session cookie (deleted when browser closes)
document.cookie = "username=ucsc;";

// Persistent Cookie expiring in 30 days
var now = new Date();
now.setMonth(now.getMonth() + 1);
document.cookie = "username=ucsc;expires=" + now.toUTCString() + ";path=/";
  • Reading & Parsing Cookies: 
    var allCookies = document.cookie; // Returns "key1=val1; key2=val2"
var cookieArray = allCookies.split(';');
for (var i = 0; i < cookieArray.length; i++) {
    var name = cookieArray[i].split('=')[0].trim();
    var value = cookieArray[i].split('=')[1];
}
  • Deleting a Cookie: Setting the expires parameter to a historical date in the past immediately forces the browser to destroy the cookie: 
    var past = new Date();
past.setMonth(past.getMonth() - 1);
document.cookie = "username=;expires=" + past.toUTCString() + ";path=/";
