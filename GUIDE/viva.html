Viva Defense Q&A: Master the Codebase

Q1: How do you get information from the database and make it visible in a form as read-only?

Examiner Goal: Testing if you understand the flow of data from DB -> PHP -> HTML.

Answer & Codebase Link: "First, we execute a SELECT query (e.g., in admin.php line 62, we fetch the user by ID). We fetch the result into an associative array $editUser. Next, inside the HTML form, we populate the input by echoing the value: <input type='text' value='<?php echo $editUser['username']; ?>' readonly>. Adding the readonly HTML attribute locks the field from user input while still allowing it to be submitted via POST."

Q2: Why did you use session_start() on every page, and how does your login work?

Examiner Goal: Testing state management understanding.

Answer & Codebase Link: "HTTP is stateless. We use PHP sessions to remember the user. In login.php, upon verifying the password against the DB, we set $_SESSION['user_id'] = $user['id'] and $_SESSION['role'] = $user['role']. At the top of admin.php or applications.php, we check if $_SESSION['role'] matches the required role. If it doesn't, we redirect them away using the header() function. This secures the system."

Q3: Why did you use require_once '../config/db.php' instead of include?

Examiner Goal: Testing error handling knowledge.

Answer & Codebase Link: "If a database connection fails, the rest of the application cannot function securely. include only throws a warning and continues executing the script, which could lead to severe errors or data leaks. require_once throws a fatal error and halts execution, which is much safer. The `_once` suffix ensures we don't accidentally declare the database connection twice, which would crash the app."

Q4: How did you prevent SQL Injection in your project?

Examiner Goal: Security basics.

Answer & Codebase Link: "In all our forms, like signup.php and the application submission in home.php, we used PDO Prepared Statements. Instead of inserting variables directly into the SQL string (which can be hijacked), we use placeholders VALUES (?, ?) and bind the variables during execution. This separates the query logic from the data."

Q5: How does your JavaScript form validation connect with your PHP backend?

Examiner Goal: Understanding client vs server architecture.

Answer & Codebase Link: "They act as two layers of defense. In admin.php, we use DOM Level 0 JavaScript (onsubmit="return checkAddUser()") to check for empty fields instantly on the client side without reloading the page. However, JavaScript can be bypassed by the user. If the JS returns true, the form is submitted to the PHP backend, which securely interacts with the database."
