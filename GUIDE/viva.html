Viva & Q&A Prep

Viva Question 1: How do you get information from the database and make it visible in a form as read-only?

Answer: First, you use a SELECT query to fetch the specific record based on an ID passed via $_GET. You fetch the row as an associative array. Then, inside your HTML form, you use PHP's echo to print the database value inside the value="..." attribute of the input. Finally, you add the readonly attribute to the HTML input tag to prevent the user from typing in it.

Project Context: Code Example

File: public/admin.php (Lines 62 & 109)

<?php
// 1. Fetch data
$stmt = $conn->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$id]);
$editUser = $stmt->fetch();
?>

<!-- 2. Display in form (with readonly example) -->
<input type="text" name="username" value="<?php echo htmlspecialchars($editUser['username']); ?>" readonly>

Note: In our actual code, the field isn't read-only because the admin needs to edit it, but adding readonly to the tag is all it takes to lock it down while still submitting the data via POST!

Viva Question 2: Why do we use htmlspecialchars() when printing data from the database?

Answer: It converts special characters to HTML entities (e.g., < becomes &lt;). This prevents Cross-Site Scripting (XSS) attacks. If a user entered malicious JavaScript as their name, htmlspecialchars() ensures it is printed as harmless text rather than executed by the browser.

Viva Question 3: How does your login system remember who is logged in across different pages?

Answer: We use PHP Sessions. At the top of every page, we call session_start(). When a user logs in successfully, we store their ID and role in the $_SESSION superglobal array (e.g., $_SESSION['role'] = 'admin'). On other pages, we check if those session variables exist; if not, we use header("Location: login.php") to kick them out.

Viva Question 4: What is the difference between include and require_once?

Answer: If an include fails (file missing), the script continues with a warning. If a require fails, it throws a fatal error and stops the script. require_once ensures the file is included exactly one time, preventing redeclaration errors (which is why we use it for db.php and headers).
