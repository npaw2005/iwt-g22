2. CSS & Layouts

1. Selectors & Combinators (High Yield)

Beyond basic `.class` and `#id`, exams heavily test how CSS traverses the HTML tree.

  • Descendant (Space): div p selects ALL p tags inside a div, no matter how deep.
  • Child (>): div > p selects only direct children. Nested p tags in a span are ignored.
  • Adjacent Sibling (+): div + p selects the single p tag immediately following the div.

Project Context: public/css/style.css

In our stylesheet, we use descendant selectors like .navbar-brand a to style links specifically inside the branding area without affecting global links. We also use pseudo-classes like .btn:hover to provide user feedback when hovering over buttons.

2. Attribute Selectors

Attribute selectors target elements based on their HTML attributes. Very common in exams:

  • [class^="abc"] : Starts with "abc"
  • [class*="abc"] : Contains "abc"
  • [class$="abc"] : Ends with "abc"

Project Context: Styling Form Inputs

In our CSS, we use input[type="text"], input[type="password"], select. This ensures our styling applies ONLY to text fields and dropdowns, so if we add a radio button or checkbox later, it doesn't accidentally get a massive padding and a 100% width.

3. Dropdown Menus & Hover States

Past Paper Trap: Dropdown CSS Construction

A guaranteed 25-mark question is filling in blanks for a dropdown menu. The formula is always:

.dropdown { display: inline-block; position: relative; }
.dropdown-content { display: none; position: absolute; }
.dropdown:hover .dropdown-content { display: block; }

4. SCSS & Preprocessors

Past Paper Trap: SCSS For Loops

You must memorize SCSS variable declarations ($primary-color: #333;) and `@for` loops. The exam tests interpolation syntax: @for $i from 1 through 3 { .col-#{$i} { width: ... } }. Missing the #{} around the variable in class names is a failure.
