1. Server Architecture & Execution Lifecycle

Syllabus TheoryClient vs Server Lifecycle

PHP (Hypertext Preprocessor) is an open-source, server-side scripting language executed sequentially on the web server before any HTML is sent to the client browser:

Execution MetricClient-Side (JavaScript)Server-Side (PHP)
Runtime EnvironmentWeb Browser (V8, SpiderMonkey)Web Server (Apache HTTPD, Nginx)
Execution TriggerUser events (clicks, input, hover)Incoming HTTP Request for .php file
Execution FlowAsynchronous / Event-drivenStrictly sequential (top-to-bottom)
Source Code VisibilityViewable in browser source viewCompletely hidden; browser receives only rendered HTML/output

3. PHP Basic Syntax, Tags & Output Constructs

Syllabus Theory<?php ... ?> + echo vs print
  • Tags: Standard opening <?php and closing ?>. Can be embedded anywhere in HTML.
  • Case Sensitivity Rules:
    • Keywords, function names, class names are case-insensitive (ECHO, echo, Echo are identical).
    • Variable names are strictly case-sensitive ($user != $User != $USER).
  • echo vs print:
    • echo: Language construct. Takes multiple comma-separated arguments: echo "A", "B", "C";. Returns nothing (void). Faster.
    • print: Takes only a single argument. Always returns 1, so it can be used in expressions: $ret = print("Hello");.

4. Variables, Constants & Scope (define vs $)

Syllabus TheoryVariable Scope & Constants
  • Variables: Prefixed with $. Dynamically typed. Local to functions unless declared with global $var; or accessed via $GLOBALS['var'].
  • Static Variables: Declared with static $count = 0; inside a function. Retains its state across function invocations.
  • Constants (define()):
    Defined via define("x", "15");. Accessed as barewords without $. Globally accessible across all functions without global.
Past Paper AlertAY21 Q2.2.a Tracing Trap
define("x", "15");
$x = x + 10;
echo x;

// EXAM OUTPUT: 15
// Explanation: echo x targets the constant 'x' (15). The variable $x is ignored.

5. Type Juggling, Operators (+ vs .) & Comparisons

Syllabus TheoryAddition vs Concatenation
  • Addition (+) vs Concatenation (.):
    • + is strictly numeric: "5" + 10 evaluates to integer 15.
    • . is strictly string concatenation: "5" . 10 evaluates to string "510".
  • Increment Operators:
    • Post-increment $x++: Returns original value, then increments.
    • Pre-increment ++$x: Increments first, then returns updated value.
  • The in_array() Loose Equality Trap:
    in_array("search", $arr) returns boolean false if not found. Under loose comparison ==, false == 0 evaluates to true!
Past Paper AlertAY22 Q3.II Output Tracing
$x = "5"; $y = 10;
echo $x + $y . " ";
echo $x . $y;
// OUTPUT: 15 510

$x = 5;
echo $x++ . " " . ++$x . " " . $x;
// OUTPUT: 5 7 7

6. Indexed, Associative & Multidimensional Arrays

Syllabus TheoryArray Types
  • Indexed Arrays: Sequential integer indices starting at 0: $fruits = ["Apple", "Orange", "Banana"];.
  • Associative Arrays: Named string keys: $user = ["username" => "ucsc", "role" => "student"];.
  • Multidimensional Arrays: Arrays containing nested child arrays: 
    $matrix = [[1, 2], [3, 4]];
echo $matrix[0][1] + $matrix[1][0]; // 2 + 3 = 5 (AY22 Q3.II.g)

7. Array Auto-Indexing & Key Casting Rules

Syllabus TheoryNext Key Assignment & Decimal String Casting
  • Next Integer Auto-Assignment ($arr[] = val):
    PHP assigns an index equal to: $$\text{Maximum Existing Integer Key} + 1$$ Even if intermediate keys are empty, PHP never backfills!
  • Decimal String Key Casting:
    Strings containing valid decimal integer representations (e.g. "2", "12") are automatically cast to standard integer keys!
    Therefore, $arr["2"] = 4; will overwrite $arr[2] = 2;!
Past Paper AlertAY21 Q2.2.d & AY22 Q3.II.i Traps
// AY21 Q2.2.d
$arr = array(5 => 1, 12 => 2);
$arr[] = 56;
$arr["x"] = 42;
// [5]=>1, [12]=>2, [13]=>56 (12+1!), ["x"]=>42

// AY22 Q3.II.i
$a = ["x" => 1, 2 => 2, 0 => 3, "2" => 4];
foreach ($a as $k => $v) { echo "($k:$v)"; }
// OUTPUT: (x:1)(2:4)(0:3)  -- "2" casts to 2 and overwrites value 2 with 4!

8. Array Functions & SPL ArrayIterator

Syllabus TheorySorting & Iteration
  • sort() / rsort(): Sorts indexed arrays ascending / descending by value (re-indexes keys from 0).
  • asort() / arsort(): Sorts associative arrays ascending / descending by value (preserves keys).
  • ksort() / krsort(): Sorts associative arrays ascending / descending by key.
  • usort($arr, 'callback'): Custom sorting using user-defined comparison function.
  • array_merge($a1, $a2): Merges arrays, renumbering numeric keys.
  • array_reduce($arr, 'callback', initial): Iteratively reduces array to single value.
  • SPL ArrayIterator: 
    $iterator = new ArrayIterator([1, 2, 3, 4, 5]);
echo iterator_count($iterator); // OUTPUT: 5 (AY21 Q3.1.b)

9. Control Flow & The Foreach Reference Leak Gotcha

Syllabus Theory&$val Pointer Leak

When iterating by reference (foreach ($nums as &$n)), each step binds $n as an address pointer to that element.

The Deadly Reference Leak Trap (AY22 Q3.II.f):

When the loop concludes, $n remains permanently bound as a reference to the very last array element! Any subsequent assignment to $n (e.g. $n = 100;) silently overwrites the last element of the array!

Past Paper AlertAY22 Q3.II.f Output Tracing
$nums = [1, 2, 3];
foreach ($nums as $n) { $n *= 2; }
foreach ($nums as &$n) { $n *= 2; }
print_r($nums); echo "<br>";
$n = 100; // Overwrites $nums[2]!
print_r($nums);

<!-- OUTPUT -->
Array ( [0] => 2 [1] => 4 [2] => 6 ) <br>
Array ( [0] => 2 [1] => 4 [2] => 100 )

10. Functions & Parameter Passing (By-Value vs By-Reference)

Syllabus Theory&$param vs $param
  • Pass by Value (Default): Function receives a copy of the argument; modifications inside the function do not affect the caller's variable.
  • Pass by Reference (&$param): The ampersand passes the memory address; modifications directly mutate the caller's variable: 
    function addFive(&$val) { $val += 5; }
$num = 20; addFive($num); echo $num; // OUTPUT: 25 (AY21 Q2.2.b)
  • Default Parameters: function greet($name = "IS1207") { echo "Welcome $name"; }

11. Superglobals & HTTP Form Handling

Syllabus Theory$_GET vs $_POST vs $_SERVER
  • $_GET: Reads URL query parameters (e.g. ?view_sid=4&view_sch=1). Visible, cached, bookmarkable, limited to ~2KB.
  • $_POST: Reads HTTP request body payload. Invisible in URL, unbookmarkable, handles arbitrary size up to post_max_size.
  • $_SERVER['REQUEST_METHOD']: Detects request verb (GET or POST).
  • Array Form Inputs: Checkboxes sharing bracket notation (name="hobbies[]") are automatically parsed by PHP into a native array in $_POST['hobbies'].

12. Session Management & Role-Based Access Control (RBAC)

Syllabus Theorysession_start() & Access Enforcement

HTTP is stateless. Calling session_start() at the top of a PHP file reads the client's PHPSESSID cookie and restores the server-side $_SESSION array:

  • Initialize session: session_start(); (Must precede all HTML output).
  • Store user data: $_SESSION['user_id'] = $user['id']; $_SESSION['role'] = $user['role'];
  • Destroy session: session_unset(); session_destroy();

14. Database Integration & Security (PDO Prepared Statements & XSS)

Syllabus TheorySQL Injection & XSS Prevention
  • Preventing SQL Injection: Never concatenate user input directly into SQL strings. Always use Prepared Statements with parameter placeholders (?). The database compiles query structure first, treating user input purely as passive data.
  • Preventing Cross-Site Scripting (XSS): Always escape dynamic outputs printed to HTML using htmlspecialchars($str), converting <, >, &, " into safe character entities.
