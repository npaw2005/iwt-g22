4. PHP & Backend

1. Superglobals & State Management

PHP uses $_GET (URL query parameters), $_POST (form data), and $_SESSION (server-side cross-page state).

Project Context: public/applications.php Detail View

In our registrar dashboard, we implemented a detailed view for applications using $_GET. We generate links like ?view_sid=4&view_sch=1. The PHP script then checks if (isset($_GET['view_sid'])), extracts the ID, and fetches the full application. This strictly adheres to the syllabus teachings on GET parameters.

2. Backend Architecture: Database Inclusion

Exams test modularity: putting database credentials in one file and the connection logic in another. They also test include vs require. (Require throws a fatal error and stops script execution if missing).

Project Context: config/db.php

We centralized our database connection in db.php. Every file uses require_once '../config/db.php';. This ensures that if the database file is missing or broken, the script halts immediately, preventing the display of half-rendered pages with sensitive variable leaks.

3. Array Mechanics & Foreach Reference Leaks

Past Paper Trap: The & Reference Leak

A classic 10-mark exam trap involves passing values by reference in a foreach loop.

$nums = [1, 2, 3];
foreach ($nums as &$n) { $n *= 2; }
$n = 100; // Because $n was a reference, this mutates the array!
// $nums is now [2, 4, 100]

Also remember array key casting: $arr["2"] = "test"; will actually be cast to integer $arr[2].

4. Server Configuration Classification

Past Paper Trap: httpd.conf vs php.ini

You must know which directives belong to which server config file:

  • Apache (httpd.conf): ServerRoot, DocumentRoot, LoadModule, PHPIniDir
  • PHP (php.ini): upload_max_filesize, display_errors
