1. Web Architecture, DNS & Browser Rendering Pipeline

Syllabus Theory 4-Phase Web Request Lifecycle

When a user types a URL (e.g., http://localhost/scholarship_system/public/login.php) into a browser, the request executes through four rigorous architectural phases:

  1. DNS Lookup Hierarchy: Resolves domain name to IP address.
    • Browser cache → OS/Router cache → Recursive DNS Resolver (ISP).
    • Hierarchy traversal: Root DNS Server (.) → TLD Server (.com, .lk) → Authoritative Name Server (returns numeric IP like 192.168.1.50).
  2. TCP & TLS Handshake:
    • TCP 3-Way Handshake: SYN (Synchronize) → SYN-ACK (Synchronize + Acknowledge) → ACK (Acknowledge).
    • TLS Handshake (HTTPS): Cipher suite negotiation, digital certificate verification, asymmetric public/private key exchange to establish a shared symmetric session key.
  3. HTTP Request / Response Transaction:
    • Browser sends HTTP Request (Method GET/POST, Headers, Payload).
    • Server (Apache/PHP) processes business logic, queries MySQL database, and returns HTTP Response (Status code 200 OK, 302 Redirect, 404 Not Found, 500 Server Error, MIME Content-Type: text/html, HTML payload).
  4. Browser Rendering Engine Pipeline:
    • DOM Construction: Parses HTML tokens into Document Object Model (DOM) tree nodes.
    • CSSOM Construction: Parses internal, external, and inline CSS into CSS Object Model (CSSOM) tree nodes.
    • Render Tree Synthesis: Merges DOM + CSSOM into Render Tree (elements with display: none are excluded; visibility: hidden elements are included).
    • Reflow / Layout: Computes the exact geometric dimensions, bounding boxes, and coordinates of every render object on screen.
    • Repaint: Rasterizes visual pixels (colors, borders, backgrounds, shadows) to the physical display buffer.
Past Paper Alert & Traps IS1207 Exam Focus

Past Paper Question: "Explain why script tags placed in the <head> without defer or async block HTML rendering."

Exam Solution: When the HTML parser encounters a <script> tag, it immediately halts DOM construction to fetch and execute the JavaScript, as JS may invoke document.write() or alter the DOM. This causes render blocking until the script execution completes.

Codebase Implementation includes/header.php (Lines 8-16) & includes/footer.php

In our project, we optimize the rendering pipeline by placing CSS stylesheets inside <head> in includes/header.php to allow early CSSOM generation, while form-validation JavaScript scripts (such as checkLogin() and checkApplication()) are placed at the bottom of the body right before includes/footer.php to prevent render-blocking of visible form controls.

2. URL Anatomy, Web Generations & Document Doctype

Syllabus Theory URL Structure + Evolution

URL Anatomy: scheme://host.domain:port/path/filename

  • scheme: Protocol (http, https).
  • host: Subdomain or machine name (www, localhost).
  • domain: Registered domain name (ucsc.cmb.ac.lk).
  • port: Port number (Default: 80 for HTTP, 443 for HTTPS, 3306 for MySQL).
  • path: Directory path on the web server (/scholarship_system/public/).
  • filename: Target resource (home.php).

Web Evolution (Web 1.0 to Web 5.0):

Generation Core Paradigm Key Characteristics
Web 1.0 Read-Only (Static) Flat HTML files, one-way passive consumption, server-side directory listings.
Web 2.0 Read-Write (Interactive) User-generated content, dynamic applications, social networks, AJAX, relational databases. (Our project falls here!).
Web 3.0 Executable / Semantic Machine-readable semantic web, RDF/OWL ontologies, smart autonomous agents.
Web 4.0 Ubiquitous / Mobile Seamless integration between physical IoT devices, wearable tech, and mobile clouds.
Web 5.0 Symbiotic / Emotional Emotional and cognitive interaction between humans and intelligent neural interfaces.

3. Semantic Layout & Text Quotation Semantics

Syllabus Theory Semantic Structural Elements

HTML5 deprecates generic <div> tags for layout in favor of meaningful semantic containers:

  • <nav>: Structural block containing primary site navigation links.
  • <header> & <footer>: Intro and footer blocks for pages or individual sections.
  • <section>: A thematic group of related content, typically beginning with an <h2>-<h6>.
  • <article>: Self-contained composition that makes sense independently.
  • <aside>: Ancillary content (sidebars, callout notes).
  • <details> & <summary>: Native expandable/collapsible disclosure widget.

Text Quotation & Typography Semantics:

  • <q>: Short inline quotation. The browser automatically injects surrounding quotation marks.
  • <blockquote cite="URL">: Block-level quotation. Renders with left and right margins/indents.
  • <abbr title="Tooltip">: Identifies acronyms/abbreviations; browser renders a dotted underline and displays tooltip on hover.
  • <address>: Author/organization contact information (rendered in italic font).
  • <bdo dir="rtl|ltr">: Bi-Directional Override to flip text direction.

4. Hyperlink Protocols & Directory Path Resolution Formula

Syllabus Theory Absolute vs Relative Directory Navigation

Mastering path traversal is a mandatory requirement tested in both exam questions and server file configuration:

  • Absolute Path: Starts with a leading slash /, indexing from the server root: <a href="/iwt/scholarship_system/public/login.php">.
  • Relative Path: Indexes from the directory of the currently executing file:
    • Same folder: href="home.php" or href="./home.php".
    • Child subfolder: href="css/style.css".
    • Parent folder (step up 1 level): href="../config/db.php".
    • Grandparent folder (step up 2 levels): href="../../index.php".
  • Same-Page Fragment Anchor: <a href="#target-id">Jump</a> jumps to <div id="target-id">.
  • Cross-Page Fragment Anchor: <a href="help.php#faq">Read FAQ</a>. (Note: Never put spaces before or after the #).
Past Paper Alert & Traps Slide 79 Exam Formula

Past Paper Question: "A web page is located at c:/b/web/k/h/2.html. Write the exact HTML code to display an image located at c:/b/web/a/f/e/1.jpg."

Mathematical Step-by-Step Resolution:

  1. Current directory is c:/b/web/k/h/.
  2. Move up one directory to k/: ../
  3. Move up second directory to web/: ../../
  4. Navigate down target tree into a/f/e/: a/f/e/
  5. Append target image: 1.jpg
<!-- THE EXACT EXAM ANSWER -->
<img src="../../a/f/e/1.jpg" alt="Photo">
Codebase Implementation public/login.php (Line 3) & includes/header.php (Line 14)

Our project demonstrates both relative path tiers:

  • In public/login.php line 3, PHP executes from public/ and needs to access config/db.php. It steps up one level: require_once '../config/db.php';.
  • In includes/header.php line 14, the browser executes the HTML in the context of the public URL, referencing the child folder: <link rel="stylesheet" href="css/style.css">.

5. Image Maps & Coordinate Geometry

Syllabus Theory <img usemap> + <map> + <area>

An Image Map enables clickable hot-spots across different geometric zones of a single image:

  • <img src="diagram.png" usemap="#map_name" alt="...">: Must have usemap attribute with a leading hash #.
  • <map name="map_name">: Container element. Must have a name attribute matching the usemap value (without hash).
  • <area shape="..." coords="..." href="..." alt="...">:
    • shape="rect": coords="x1, y1, x2, y2" (Top-left X, Y, Bottom-right X, Y). Exactly 4 integers.
    • shape="circle": coords="center_x, center_y, radius". Exactly 3 integers.
    • shape="poly": coords="x1, y1, x2, y2, x3, y3, ...". Series of X,Y vertex coordinate pairs (even number of values).
Past Paper Alert & Traps Guaranteed Q1 Syntax Trap

Past Paper Question Trap (AY21 Q1 & AY22 Q1): The examiner tests image maps every single year with 3 traps:

<!-- WRONG (Zero Marks) -->
<img src="plan.jpg" usemap="campus">  <!-- ERROR 1: Missing # -->
<map id="campus">                     <!-- ERROR 2: Uses id instead of name -->
    <area shape="rectangular" coords="10,20,50,80" src="p1.html"> <!-- ERROR 3: shape must be 'rect'; uses src instead of href -->
</map>

<!-- FULLY CORRECTED VERSION -->
<img src="plan.jpg" usemap="#campus" alt="Campus Plan">
<map name="campus">
    <area shape="rect" coords="10,20,50,80" href="p1.html" alt="Room 1">
</map>

6. Semantic Tables & Spanning Grids

Syllabus Theory <table> Structural Model

HTML tables organize relational information into rows and columns:

  • <table>: Root table wrapper.
  • <caption>: Accessible table title. Must be placed immediately after <table> before any <tr>!
  • <thead>: Table header section containing column headings in <th> cells.
  • <tbody>: Core data section containing data in <td> cells.
  • <tfoot>: Summary/calculation footer section.
  • Spanning Rules:
    • colspan="N": Merges cell across $N$ columns horizontally.
    • rowspan="N": Merges cell across $N$ rows vertically.
Past Paper Alert & Traps Guaranteed 25-Mark Drawing Grid (Q2)

Past Paper Question Trap (AY21 Q2 & AY22 Q2): You are given an HTML table and required to sketch the browser output grid:

  • The TFOOT Placement Gotcha: In HTML specifications, <tfoot> can be authored physically above <tbody> in the raw code. However, the browser ALWAYS renders <tfoot> at the absolute bottom! If you draw the footer in the middle of the table, you lose all marks.
  • Subsequent Row Cell Counts: When a cell in row 1 has rowspan="3", row 2 and row 3 will have one less <td> tag in their markup because the spanned cell physically occupies that slot!

7. HTML Forms, Input Types & Readonly Architecture

Syllabus Theory Form Mechanics & Enctypes

Forms transmit user data across HTTP to a server processing script:

  • <form action="home.php" method="POST" name="appForm" onsubmit="return checkApplication()">
  • Form Enctypes:
    • application/x-www-form-urlencoded: Default URL-encoded payload.
    • multipart/form-data: Mandatory whenever uploading files (<input type="file">).
    • text/plain: Raw unencoded text (used with action="mailto:...").
  • <fieldset> & <legend>: Encapsulates themed form subsections with an accessible outline and caption.
  • The Crucial Difference: readonly vs disabled:
    • readonly: Prevents user modification in browser UI, but IS submitted in the HTTP request payload!
    • disabled: Greys out the input, prevents user focus, and is completely excluded from the HTTP request payload!

8. Framesets, IFrames & Media Directives

Syllabus Theory Window Targeting & Inline Frames

Frameset Rules (Legacy Multi-Frame Architecture):

  • <frameset> replaces the <body> tag entirely. A document cannot have both <frameset> and <body> (except inside <noframes>).
  • Splitting layout: <frameset rows="20%, 80%"> or <frameset cols="250, *">.
  • Reserved Target Frame Names:
    • _self: Default. Loads target into the current frame.
    • _blank: Loads target into an entirely new browser tab/window.
    • _parent: Breaks out one level into the immediate parent frameset.
    • _top: Breaks out of all nested framesets to take over the full window.
  • Inline Frames (<iframe>): Embedded directly inside normal <body> to load sandboxed child documents: <iframe src="help.php" width="600" height="400" title="Help Frame"></iframe>.
