📋 UCSC IS1207 Examination Blueprint (100 Marks)

Both AY21 and AY22 semester exam papers strictly enforce an identical four-question architecture, each carrying exactly 25 marks. Understanding this macro-structure is essential for maximum scoring:

Question Primary Domain Tested Capabilities High-Yield Focus Areas
Question 1 (25M) HTML & CSS Syntax & Error Identification Identify whether given snippets are valid or invalid; provide exact corrections. <meta> placement inside body, href vs src in anchors, image map usemap # syntax, CSS property spelling (font-family vs font-type), length units, Sass @for loops & variable interpolation.
Question 2 (25M) Visual Output Prediction & UI Components Sketch rendering grids, predict CSS cascade/combinators, write complete CSS widgets. Table rendering with intersecting rowspan and colspan, <tfoot> positioning gotchas, pure CSS hover dropdown menus (display: none to block), CSS counters.
Question 3 (25M) JS & PHP Code Tracing, Server Configurations Trace script execution outputs, classify web server vs runtime directives. JS strict (===) vs loose (==) equality, modulo loop outputs, PHP type juggling (+ vs .), array auto-indexing, foreach reference leaks (&$val), Apache httpd.conf vs PHP php.ini directives.
Question 4 (25M) Relational SQL & PHP Backend Architecture Write complete DDL schemas with Foreign Keys, construct DML CRUD queries, write modular PHP connection scripts. CREATE TABLE with composite PKs & FKs, modular configuration (value.php + con.php), PDO / MySQLi prepared statements (prepare(), execute()), multi-table JOIN queries rendered into HTML tables.

🏛️ Project Architecture: Scholarship Management System

Codebase Map /home/niduka/iwt/scholarship_system/

Our project implements a secure, normalized web application running on Apache/PHP/MySQL (XAMPP). It is built entirely without third-party frameworks or libraries to strictly satisfy course rubric constraints:

Component / Directory File Path Role & Architectural Purpose
Database Schema schema.sql Normalized relational database (scholarship_db) with 4 tables: users, students, scholarships, and student_scholarships. Enforces foreign key constraints with ON DELETE CASCADE.
Database Config config/db.php Modular PDO database connection establishing connection persistence, UTF-8 character encoding, and PDO::ERRMODE_EXCEPTION error handling.
Modular Layout includes/header.php & includes/footer.php Dynamic navigation bar enforcing session-based role visibility (Guest, Student, Registrar, Admin). Standardizes HTML5 doctype, metadata, and stylesheets across all views.
Student Portal public/home.php Multi-state view: Guest listing, Student scholarship browser, multi-section application form with pre-filled read-only profile data, and personal application history table.
Registrar Control public/applications.php Scholarship lifecycle management (add, remove) and application processing. Implements drill-down application review via $_GET['view_sid'] with approval/rejection workflows.
Administrator Panel public/admin.php System reporting dashboard (live SQL aggregation), user management CRUD (add, edit, safe delete), and system-wide application overview.
Authentication public/login.php, public/signup.php, public/logout.php Secure authentication handling session initialization, duplicate username checks, client-side DOM Level 0 validation, and session destruction.
Styling Engine public/css/style.css Pure CSS3 stylesheet utilizing float-based layout, clearfix techniques, attribute selectors, pseudo-classes, gradient buttons, and responsive tables without external frameworks.
