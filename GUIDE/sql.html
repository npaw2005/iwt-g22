1. Relational Database Foundations & Terminology

Syllabus TheoryRelational Model (E.F. Codd, 1970)

A relational database organizes data into structured tables governed by relational algebra:

  • Relation (Table): A two-dimensional grid representing a specific entity set.
  • Tuple (Row / Record): A single horizontal row containing data for one entity instance.
  • Attribute (Column / Field): A vertical column representing a named property of the entity.
  • Attribute Domain: The set of permitted, valid data values for that attribute (e.g. integer, date).
  • Relation Schema: The structural blueprint of a relation: Table_Name(Attribute_1, Attribute_2, ...).

4. Relational Database Anomalies

Syllabus TheoryInsertion, Update & Deletion Anomalies

Un-normalized tables suffer from three destructive operational anomalies:

  • Insertion Anomaly: Inability to insert information about an entity without artificially fabricating or supplying NULL values for another entity. (e.g. Cannot define a new scholarship if no student has applied yet).
  • Update Anomaly: Data inconsistency caused by updating information in one row while leaving redundant duplicate copies un-updated in other rows.
  • Deletion Anomaly: Deleting one entity record accidentally and unintentionally destroys all data about a completely separate entity.

5. DDL Database & Table Construction

Syllabus TheoryCREATE DATABASE & CREATE TABLE

Data Definition Language (DDL) defines table structures and is auto-committed permanently:

CREATE DATABASE IF NOT EXISTS scholarship_db;
USE scholarship_db;

CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    role VARCHAR(20) NOT NULL DEFAULT 'student',
    email VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

6. Column Constraints & Auto-Increment

Syllabus TheoryConstraints Matrix
  • NOT NULL: Ensures column cannot store NULL empty values.
  • UNIQUE: Enforces that all values in the column are distinct across all rows.
  • DEFAULT val: Supplies fallback value when an insert statement omits the column.
  • AUTO_INCREMENT: Automatically assigns an incrementing integer upon new row insertion.
  • CHECK (condition): Restricts data values to a specific range or rule.

7. Primary & Composite Keys Construction

Syllabus TheoryJunction Tables & Composite PKs

A composite primary key enforces uniqueness across multiple columns simultaneously:

CREATE TABLE student_scholarships (
    student_id INT NOT NULL,
    scholarship_id INT NOT NULL,
    purpose VARCHAR(255),
    status VARCHAR(20) DEFAULT 'pending',
    applied_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (student_id, scholarship_id)
);

Effect: A student can apply to multiple scholarships, and a scholarship can receive applications from multiple students, but a student cannot apply to the same scholarship twice!

8. Foreign Keys & Referential Actions (ON DELETE CASCADE)

Syllabus TheoryCASCADE vs SET NULL vs RESTRICT
  • FOREIGN KEY (child_col) REFERENCES parent_table(parent_col): Enforces referential integrity.
  • ON DELETE CASCADE: When a parent record is deleted, the database engine automatically deletes all child records referencing it!
  • ON DELETE SET NULL: Sets child foreign key to NULL when parent is deleted.
  • ON DELETE RESTRICT: Blocks parent deletion if child references exist.

12. Pattern Matching & Filtering (LIKE, BETWEEN, IN)

Syllabus TheoryWildcards & Range Filtering
  • LIKE '%tech%': Matches strings containing "tech" anywhere.
  • LIKE '_d%': Matches strings where the second character is 'd'.
  • BETWEEN 20000 AND 80000: Inclusive numerical or date range check.
  • IN ('admin', 'registrar'): Matches if value exists within target set.
  • IS NULL / IS NOT NULL: Checks for absence or presence of value.

13. Aggregate Functions & The HAVING Rule

Syllabus TheoryCOUNT, SUM, AVG & GROUP BY

The Fundamental HAVING Rule (Slide 69):

In SQL, the WHERE clause cannot filter on aggregate functions because WHERE filters individual records before aggregation occurs. The HAVING clause was introduced specifically to filter grouped records after aggregation!

-- WRONG (Syntax Error)
SELECT role, COUNT(*) FROM users WHERE COUNT(*) > 2 GROUP BY role;

-- CORRECT RE-WRITE
SELECT role, COUNT(*) FROM users GROUP BY role HAVING COUNT(*) > 2;

14. Relational Joins: 4-Table Production Queries

Syllabus TheoryINNER JOIN vs LEFT OUTER JOIN
  • INNER JOIN: Returns records with exact matching foreign keys in both tables.
  • LEFT JOIN: Returns all records from left table, with matching or NULL attributes from right table.
  • $N - 1$ Join Predicate Rule: Joining $N$ tables requires at least $N - 1$ distinct ON conditions to avoid Cartesian products.
Codebase Implementationpublic/applications.php (Line 41)
41: $stmt = $conn->query("SELECT ss.*, u.username, u.email, st.full_name, st.name_with_initials, st.dob, st.gender, st.parents_income, st.parents_occupation, st.gpa, st.permanent_address, st.nic, st.contact_numbers, s.name AS scholarship_name 
    FROM student_scholarships ss 
    INNER JOIN users u ON ss.student_id = u.id 
    LEFT JOIN students st ON u.id = st.user_id 
    INNER JOIN scholarships s ON ss.scholarship_id = s.id 
    ORDER BY ss.applied_at DESC");

Viva Defense: "We used a LEFT JOIN on students because if a student applies before completing their optional profile, an INNER JOIN would have completely hidden their application from the Registrar. The LEFT JOIN keeps the application visible with NULL profile fields."
