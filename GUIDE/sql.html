SQL - Structured Query Language

Concept: Data Definition Language (DDL) & Foreign Keys

The syllabus requires you to write CREATE TABLE statements, specifically focusing on Primary Keys (AUTO_INCREMENT) and Foreign Keys linking parent and child tables.

General Code Example (Exam Style)

CREATE TABLE enrollments (
    enroll_id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT,
    course_id INT,
    FOREIGN KEY (student_id) REFERENCES students(student_id)
);

Project Context: Where is this used?

File: schema.sql

Explanation: Our project uses this exact pattern extensively. The student_scholarships table uses a composite primary key and foreign keys to link to the users and scholarships tables. We also use ON DELETE CASCADE which ensures that if a scholarship is deleted, all applications for it are also automatically deleted.

CREATE TABLE student_scholarships (
    student_id INT NOT NULL,
    scholarship_id INT NOT NULL,
    PRIMARY KEY (student_id, scholarship_id),
    FOREIGN KEY (student_id) REFERENCES users(id) ON DELETE CASCADE
);

Concept: Database Connection & Prepared Statements

Exams test modular architecture (splitting config into value.php and con.php). They also test CRUD operations using MySQLi prepared statements (prepare(), bind_param(), execute()) or PDO.

Project Context: Where is this used?

File: config/db.php & public/admin.php

Explanation: We implement this modular architecture. config/db.php holds our PDO connection string. In admin.php, when adding a user, we use a prepared statement to prevent SQL injection, which perfectly mirrors the exam requirements.

$stmt = $conn->prepare("INSERT INTO users (username, password, email, role) VALUES (?, ?, ?, ?)");
$stmt->execute([$username, $password, $email, $role]);
